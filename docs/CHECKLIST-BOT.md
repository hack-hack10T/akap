# Чек-лист: создание бота и подключение оплат

Единственный шаг, который нельзя автоматизировать, — создание Telegram-бота:
это делает только @BotFather, под тем аккаунтом, на который оформляется бот
(для магазина A CUP — аккаунт Аркадия Викторовича). Всё остальное
(деплой, webhook, секреты) автоматизировано — см. ветку `feat/bot-deploy`.

---

## 1. Создать бота (2–3 минуты, с телефона/десктопа Аркадия)

1. В Telegram открыть **@BotFather** (официальный бот создания ботов).
2. Отправить команду: `/newbot`
3. На вопрос «Send a name for your bot» — имя бота, например:
   `A CUP — кофейный гайд`
4. На вопрос «Send a username for your bot» — юзернейм **обязательно заканчивается на `bot`**,
   латиницей, уникальный, например:
   `acup_guide_bot`
   (если занят — BotFather предложит/попросит другой).
5. BotFather пришлёт сообщение с **токеном** вида:
   `1234567890:AAH...` — это и есть `BOT_TOKEN`.

> ⚠️ Токен = пароль от бота. Никому не передавать, хранить в секретах Worker
> (не в git!). Наш бот кладёт его через `wrangler secret put BOT_TOKEN`.

---

## 2. Подключить оплату картой (ЮKassa) — опционально, но желательно

Без этого шага кнопка «💳 Купить за 299 ₽» работает через **ссылку на оплату
ЮKassa** (покупатель уходит на страницу оплаты, токен доступа после оплаты
приходит в чат автоматически). С этим шагом покупка картой происходит
**нативным инвойсом прямо в чате** — удобнее.

### 2a. Получить provider-токен в кабинете ЮKassa
1. Войти в кабинет ЮKassa (тот же магазин, что подключён к сайту акуп.рф).
2. Раздел **Настройки → Ключи API** (или «Интеграция»).
3. Найти блок **«Ключ для Telegram-ботов»** → выпустить/скопировать.
   Это и есть `YOOKASSA_PROVIDER_TOKEN`.

### 2b. Привязать в BotFather
1. В **@BotFather**: `/mybots` → выбрать созданного бота.
2. Меню **Bot Settings → Payments** (или сразу пункт **Payments**).
3. Выбрать провайдера **ЮKassa** → вставить provider-токен из шага 2a.

---

## 3. Передать токены в деплой

1. Прислать `BOT_TOKEN` (и `YOOKASSA_PROVIDER_TOKEN`, если делали шаг 2)
   тому, кто запускает деплой (в нашем случае — Hermes-агенту в личку,
   либо вставить самому в команды ниже).
2. Далее по инструкции `deploy/DEPLOY-BOT.md` из ветки `feat/bot-deploy`:

```bash
export BOT_TOKEN="..."
export BOT_WEBHOOK_SECRET="$(openssl rand -hex 24)"
export YOOKASSA_PROVIDER_TOKEN="..."   # опционально
./deploy/set-secrets.sh
npx wrangler@4.118.0 deploy
./deploy/set-webhook.sh
```

## 4. Проверить (тест-план)

| Шаг | Ожидание |
|---|---|
| Открыть бота, `/start` | Приветствие + кнопки: 💳 299 ₽, ⭐ 165, 📖 Что внутри, 🔑 Мой доступ |
| «📖 Что внутри» | Описание глав |
| «⭐ Купить за 165 ⭐» | Нативный инвойс в Stars → после оплаты приходит токен `ACUP-…` + ссылка на вход |
| «💳 Купить за 299 ₽» | Инвойс (если есть provider-токен) или ссылка ЮKassa; после оплаты токен приходит в чат |
| «🔑 Мой доступ» | Повторно присылает токен последнего оплаченного заказа |
| Владелец: `/stats` | Продажи за 24 ч |
| Владелец: `/refund <AC-XXXX>` | Возврат (карта — через ЮKassa, Stars — через refundStarPayment), доступ отзывается |
| Сайт после оплаты | Токен работает и на сайте (`/login`) — доступ общий |

---

## 5. Важно

- Возврат автоматически отзывает доступ: сессии в `sessions` помечаются
  `revoked_at`, справочник перестаёт открываться по токену.
- Продажи из бота пишутся в ту же таблицу `orders` (источник виден по
  заполненным `tg_user_id`/`tg_chat_id`), владельцу уходит уведомление в Telegram.
- Чек для «Мой налог»: как и на сайте, после продажи требуется регистрация
  чека (поле `receipt_status='receipt_pending'`).
